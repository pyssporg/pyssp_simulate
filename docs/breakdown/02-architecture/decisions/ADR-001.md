# ADR-001: Comparison Moves to `pyssp_vv`

**Status:** Accepted
**Layer:** architecture-decision

---

## Context

This package shipped `compare.py`: cross-engine and reference-CSV comparison,
with `PairReport.passed(atol, rtol)`, a `compare` CLI subcommand, and a
`compare` block in the permutation config. That gave `pyssp_simulate` a second
reason to change — numerical practice — alongside engines, and put acceptance
logic inside a simulation substrate.

`ComparisonWindow`, `compare_to_reference`, and `SimulationResult.from_reference_csv`
were added in 0.1.1 to satisfy a consumer's analysis requirements. That is the
signature of a misplaced abstraction.

No project outside `pyssp_simulate` imported `compare`, `compare_to_reference`,
`PairReport`, or `ComparisonWindow`, and no script invoked
`pyssp-simulate compare`. The extraction cost was one internal module.

## Decision

Remove comparison from this package.

- Measurement and judgment live in `pyssp_vv`: `pyssp_vv.measure` for
  trajectories, alignment, and metrics; `pyssp_vv.judge` for criteria and
  verdicts.
- `compare.py`, the `compare` CLI subcommand, and the comparison exports are
  removed. Version bumps to 0.2.0.
- The `compare` key in permutation configs is rejected, so an old config fails
  loudly instead of silently losing its tolerance.
- `permutations` may import `pyssp_vv.measure` locally, for the convenience of
  reporting metrics inside a sweep. That surface is not re-exported, and
  `pyssp_vv.judge` is never imported.
- `PermutationRun.report` becomes `measurements`, and `PermutationRun.passed`
  is removed. `run-all` reports metrics and does not return a verdict.

## Consequences

- `pyssp_simulate` has one reason to change: engines and SSP runtime.
- The public API no longer contains an acceptance decision.
- Measurement is an optional dependency (`pyssp-vv[measure]`). Base installs
  import and simulate without it; a multi-backend permutation without the extra
  raises an actionable `ImportError`.
- Consumers that scripted `pyssp-simulate compare` must move to `pyssp_vv`.
  No such consumer was found in the pyssp organization.
- Re-exporting the measurement surface here would undo the decision; the import
  stays local to `permutations`.

## Alternatives considered

1. **Keep `compare` and add judgment later.** Rejected: leaves two
   implementations and two reasons to change.
2. **Keep `compare` but drop `passed()`.** Rejected: the remaining
   reference-CSV and window handling still belongs to analysis, and metrics
   would sit far from the judgment that consumes them.
3. **Depend on `pyssp_vv` at module scope.** Rejected: it would make the
   substrate uninstallable without the measurement extra, for a capability only
   permutations need.
